# 架构与设计决策

## 照片墙渲染引擎（src/core/）

### 世界坐标系

- `WORLD_COLS=20` × `WORLD_ROWS=15` = 300 个槽位
- `STEP=340`，世界尺寸 `WORLD_W=6800` × `WORLD_H=5100`
- 20 张图在 300 个槽位里**循环复用**，每张图被 15 个槽位共用
- 图片分配公式：`imageIndexAt(col, row) = ((col*47 + row*31) % 20 + 20) % 20 + 1`

### 核心设计：可见性过滤与定位合并

**旧实现（已废弃）**有两个独立计算互相矛盾：可见性过滤用滚动原点算，定位却用屏幕中心重新找最近格子，
导致约 23% 通过过滤的卡片实际被放到视口外，白白付出 10 次 k 循环 + 样式写入。

**现实现**：直接用取模数学一次算出每张卡的屏幕位置，不再做 k=-2..2 的循环搜索。
`cellX = (wrappedCol + WORLD_COLS*m) * currentStep - scrollX` —— 注意 **scrollX 是摄像机左边界**，
scrollX 增大 = 摄像机右移 = 内容在屏幕上向左移动。

### 渲染循环的关键优化

- **样式差分写入**：只有几何真的变了才写 style，静止帧写入次数 = **0**（旧版 450~600）
- **卡片延迟回收**：离开视口 4 秒后才 detach，避免频繁进出时反复创建
- **零布局读取**：渲染路径中不调 `getBoundingClientRect`，尺寸从 `imageManifest` 的 w/h 推算
- **dt 归一化**：惯性衰减按实际帧间隔归一，60/120/144 Hz 手感一致

### 状态变更必须调 scheduleUpdate()

这是**踩过的坑**：`setHover()` 只改状态不驱动渲染，因为悬停判定发生在渲染循环内部。
（当时）全项目 11 处状态变更都调了 `scheduleUpdate()`，唯独 `onHoverMove`/`onHoverOut` 漏了，
导致悬停放大完全失效。**新增任何状态变更都要记得调。**

## 转场：ptr 擦除覆盖层（src/components/PtrTransition.vue）

### 为什么用覆盖层而不是 View Transitions

曾经实现过 `document.startViewTransition` 的 3D 立方体版本，但参考站实际用的是
**自己实现的覆盖层**（代号 ptr）。已删除 VT 版（`src/core/pageTransition.js`）。

### 三段斜向擦除

三层 `.ptr-wipe-a` / `-b` / `-main`，每层内是 `skewX(-10deg)` 的填充块。
- 擦入（cover）：延迟 a=0s / b=0.06s / main=0.12s
- 擦出（reveal）：顺序反转 main=0s / b=0.06s / a=0.12s
- 时长 `.28s cubic-bezier(.7,0,.2,1)`
- `--ptr-x` 按方向注入：next=1（右侧进）、prev=-1（左侧进）

### 状态机

`null` → `{dir, phase:'cover'}` → `'reveal'` → `'idle'` → `null`

- **route push 发生在 toReveal() 内、phase 切到 reveal 之前** ——
  即「擦入盖住 → 切路由 → 擦出揭示新页面」
- 动画事件驱动：`ptr-wipe-in` 的 animationend 触发 toReveal，`ptr-wipe-out` 触发 finish
- **覆盖层必须常驻挂载（不能加 v-if）** —— 转场第一步是擦入盖住，
  按需挂载会先闪一帧旧页面

### 关键时序修正（我方优于参考站的地方）

参考站用 `Promise.all([就绪信号(1500), minCover(440)])`，由 1500ms 决定，
（注：参考站那个 helper 看着像字体等待，**其实不是**，所以 PtrTransition.vue 里刻意不叫 `waitForFonts`，别按那个名字去「修」它）
导致擦入结束到擦出之间**空等约 1483ms**，总时长 2.47s。

我方改为 `Promise.race([readySignal, pushReady])` 与 `minCover(440)` 竞速：
- 空等降到 **420~470ms**
- 总时长 **1.35s**（省约 1.1s）
- 必须保留 440ms 最短覆盖，否则覆盖层没铺满就擦出会露旧页面

### 方向判定

`ROUTE_ORDER = ['/', '/wall', '/cinema', '/pictorial']`
不在表内或起止相同 → 回退 `'next'`（**不是跳过动画**）。

## 影院页（src/views/Cinema.vue）

7 列斜向照片流 + 上下霓虹跑马灯。
- `.cinema-tilted { transform: rotate(-10deg) scale(1.1) }}`
- 列方向交替：1/3/5/7 向下、2/4/6 向上
- 每列时长 55/62/50/68/58/64/52 秒
- 无缝循环靠 `translateY(-50%)`，因此每列内容必须复制一份
- **列偏移乘数与列内步长都必须与 20 互质** —— 见缺陷记录

## 画报页（src/views/Pictorial.vue）

瀑布流卡片，复刻参考站首页。
- 列分配：贪心平衡（逐张放入累计高度最短的列）
- 挂载后 `measureHeights()` 用 `offsetHeight` 实测纠正估算
- 滚动入场用 `IntersectionObserver`（`rootMargin: '240px 0px'`）
- 断点：`>=1024` → 5 列，`>640` → 3 列，否则 2 列

### 3D 倾斜视差（逐字复刻参考站）

悬停时 6 个自定义属性，系数与参考站完全一致：

| 属性 | 公式 | 上限 |
|---|---|---|
| `--tilt-x` | `-(2*r*6)` | ±6deg |
| `--tilt-y` | `(2*n*8)` | ±8deg |
| `--card-par-x` | `(2*n*10)` | ±10px |
| `--card-par-y` | `(2*r*6)` | ±6px |
| `--tilt-shadow-x/y` | `-(2*n*12)` / `-(2*r*12)` | ±12px |

`n = clamp((x-cx)/w, -0.5, 0.5)`，`r = clamp((y-cy)/h, -0.5, 0.5)`

- 只在 `(hover: hover) and (pointer: fine)` 且非 reduced-motion 下启用，**setup 时算一次**
- 指针进入只量一次矩形，移动过程不读布局，写样式用 rAF 合并
- 过渡：静止 `0.45s cubic-bezier(.23,1,.32,1)`，倾斜中 `0.12s ease-out`

## 全局样式约定（src/assets/main.css）

- `--theme-color` / `--font-sans` 变量
- `color-scheme: dark`
- 全局滚动条隐藏（含 `scrollbar-width: none`）
- **`@media (prefers-reduced-motion: reduce)` 把 `animation-duration` 压到 0.01ms** ——
  这会打死所有依赖动画的循环效果，新增动画必须加放行规则
- `:focus-visible` 全局描边
